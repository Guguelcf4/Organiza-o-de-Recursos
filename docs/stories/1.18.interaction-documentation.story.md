# Story 1.18 — Documentação das superfícies expostas

## Status
Draft

## Atribuição e gate
- executor: `@dev`
- quality_gate: `@qa`
- quality_gate_tools: inventário de superfícies, conferência doc/comportamento e inspeção de acessos
- agentes especializados previstos: `@qa` (verificação de documentação), `@architect` (contratos de interação)

## Story
**Como** usuário ou consumidor de uma superfície do produto, **quero** documentação coerente com os fluxos realmente disponíveis, **para** entender como consultar e operar o sistema.

## Fontes e dependências
- FR-14 e NFR-05; PRD §§4, 7 e 10; Arquitetura ADR-006.
- Dependências: 1.2–1.17.
- Critérios legados: documentação associada aos AC-33–34 e AC-31.

## Escopo
Documentar fluxos CLI e UI efetivamente expostos. Documentar API somente se uma API vier a ser exposta; esta story não determina a criação de API nem seu público.

## Critérios de aceite
1. Inventário identifica as superfícies e fluxos realmente disponibilizados ao usuário.
2. Cada fluxo público/operacional tem instruções e resultados observáveis correspondentes; a documentação coincide com o comportamento entregue.
3. API é documentada se e somente se houver API exposta; não se presume sua existência.
4. Documentação não descreve como disponível fluxo inexistente nem omite uma superfície exposta.
5. Documentação de comandos iniciais, configuração e migrations de 1.2 permanece atualizada com as decisões de implementação efetivamente tomadas.

## Definition of Done
- Revisão manual compara inventário, documentação e comportamento observável.
- Ponto de interação novo ou alterado atualiza a documentação junto com a mudança.
